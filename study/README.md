# study — 한국어 공부 기록

이 레포를 공부하면서 남기는 **한국어 학습 노트**입니다. 블로그 초안을 겸합니다.

## 이건 번역이 아닙니다

`phases/**/docs/ko.md` 가 아니라 `study/` 에 따로 쌓는 이유가 있습니다.

- `docs/ko.md` 는 CONTRIBUTING 상 **`en.md` 의 번역** 슬롯입니다. 업스트림
  기여를 전제로 한 자리라, "제가 여기서 헷갈렸습니다" 같은 1인칭 기록이
  들어가면 안 됩니다.
- 여기 노트는 원문 요약이 아니라 **원문 + 직접 돌려 본 결과 + 막혔던 지점**의
  합성물입니다. 원문에 없는 내용이 절반입니다.

나중에 순수 번역을 기여하고 싶어지면 그때 `docs/ko.md` 를 따로 만들면 됩니다.
두 개는 목적이 다릅니다.

## 자리

```
study/
├── README.md          이 파일
├── glossary-ko.md     용어 표기 기준 — 노트 쓰기 전에 여기부터
└── phase-NN/
    └── MM-lesson-slug.md
```

파일명은 원문 레슨 디렉터리 슬러그를 그대로 씁니다. `phases/00-setup-and-tooling/01-dev-environment`
→ `study/phase-00/01-dev-environment.md`. 원문과 1:1 로 붙어 있어야 나중에 찾습니다.

## 노트 한 편의 뼈대

`phase-00/01-dev-environment.md` 가 기준 샘플입니다.

1. **문제 제기형 훅** — 결론이 아니라 마찰에서 시작. "이 레슨을 왜 건너뛰고 싶었는가"
2. **개념 소제목 2~4개** — 라벨(`## 개요`)이 아니라 미니 주장(`## 네 개의 층 — 아래에서 위로`)
3. **직접 돌려 본 결과** — 레슨 코드를 실제 실행한 출력. 지어내지 않습니다
4. **막힌 지점 / 헷갈린 것** — 이 노트의 핵심. 대화하며 풀린 오해를 그대로
5. **다음에 할 일**
6. **회수형 한 줄** — 훅에서 던진 감정으로 되돌아오며 닫기

## 규칙

- **문체는 `blog` 스킬의 slnu21 목소리.** 따뜻한 1인칭 합쇼체, 라틴어와 조사
  사이 띄어쓰기(`Python 을`, `CUDA 를`), 볼드 · `인라인 코드`.
- **용어는 `glossary-ko.md` 표를 따릅니다.** 표에 없으면 정책대로 정하고 표에 추가.
- **실행 결과는 실제 출력만.** 안 돌려 봤으면 안 돌려 봤다고 씁니다.
- **막힌 지점을 미화하지 않습니다.** 틀렸던 이해를 그대로 남기는 게 나중에 제일
  쓸모 있습니다.

## CI 에 영향 없음

`build_catalog.py` 와 `audit_lessons.py` 는 `phases/` 아래 `en.md` 만 봅니다.
`study/` 에 뭘 쌓아도 `catalog.json` 드리프트나 감사 실패가 나지 않습니다.
`site/build.js` 도 마찬가지로 이 폴더를 읽지 않습니다.
